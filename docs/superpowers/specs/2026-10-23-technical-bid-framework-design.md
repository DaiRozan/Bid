# 建筑与市政工程技术标生成系统框架设计

日期：2026-10-23

## 1. 目标与范围

建立一个 Windows 本地运行、单用户使用的技术标编制工作台。首个可运行版本必须支持实际招标文件上传和持久保存、基础文本解析及出处定位、项目事实与编制要求人工确认、目录编辑、章节编写与真实模型生成、基础规则检查，以及可编辑 DOCX 审核稿导出。

只覆盖建筑和市政工程的施工组织设计，不处理商务标、资质、报价、签章或投标提交。目标页数为可配置值，不通过重复内容凑页数。尚未实现的 OCR、语义/向量检索、规范现行性核验、专业计算、实际渲染分页及评审质量验证必须明确标记为未接入或未验证。

不提供运行时演示模式或虚构演示项目。自动化测试可以使用隔离的测试夹具，但产品界面和生成接口不得将固定文本伪装成真实解析、检索、生成或审查结果。

## 2. 技术与部署结构

- 后端：Python、FastAPI、Pydantic、SQLAlchemy、SQLite。
- 前端：Vue 3、TypeScript、Vite；以真实 REST API 驱动页面。
- 原文件和导出文件：工作区内 `data/` 按项目分目录保存，数据库保存元数据及相对路径。
- 文档处理：`python-docx` 提取和生成 DOCX，`pypdf` 提取文字型 PDF；扫描件及不能可靠处理的结构保留原文件并进入待处理状态。
- 模型：经 OpenAI 兼容接口接入 DeepSeek。请求地址为 `https://api.deepseek.com`，请求模型标识为 `deepseek-flash`，对应文档所列版本 DeepSeek-V4.1-Flash-1017。模型名、地址和密钥均由后端环境配置读取。
- 本地启动：提供 Windows PowerShell 启动脚本及中文 README；开发时代理 `/api` 到 FastAPI，构建后由 FastAPI 提供前端静态资源，尽量形成单一入口。
- 项目为单用户本地工具，首版不加入账号、权限、多租户、外部部署或企业运维设施。

建议目录：

```text
backend/
  app/
    api/          # HTTP 路由及请求/响应契约
    models/       # SQLAlchemy 数据模型
    services/     # 业务流程、版本失效、校验
    adapters/     # 解析器、模型、检索及 DOCX 导出适配器
    main.py
frontend/
  src/
    pages/        # 项目列表及编制工作区页面
    components/   # 可复用表单、表格、状态与编辑组件
    api/          # 后端客户端
data/
  projects/       # 按项目隔离的原始文件和导出文件
  knowledge/      # 用户导入的案例与规范资料
tests/
docs/superpowers/specs/
README.md
run.ps1
```

## 3. 工作流程与模块职责

1. 用户创建建筑或市政项目。
2. 上传招标文件及补遗；原文件按项目保存，记录摘要、版本和解析状态。
3. 解析 DOCX 段落/表格和文字型 PDF 页面，生成带出处的解析片段。失败项保留原文件、失败原因和重试入口。
4. 从本项目资料中整理事实候选和编制要求。候选显示原文、原始值、出处和确认状态；用户可确认、修改或标记缺失。来源冲突并列呈现，不自动猜测最终值。
5. 用户确认事实版本，选择模板，编辑章节目录及篇幅配置。
6. 按章准备输入包：章节目标、对应要求、已确认项目事实、适用知识条目和篇幅预算。只有确认可用的本项目事实作为项目数据输入；案例和规范保留资料类别及出处。
7. 调用 DeepSeek 生成结构化章节草稿。输出保存引用、依赖事实版本和待确认项；关键资料缺口不以猜测填补。
8. 用户编辑章节形成新版本，运行确定性检查并处理问题。
9. 导出可编辑的 Word 审核稿，记录来源版本、章节版本、未解决问题及页数未验证状态。

前端首屏为项目列表，不做营销落地页。项目工作区以任务流呈现项目资料与事实、编制要求与目录、章节编辑、案例规范、检查与导出。未接入能力、来源位置、待确认状态、任务进度和模型错误在对应操作位置可见，不要求用户查看后台日志。

## 4. 数据模型与来源边界

- `Project`：编号、名称、工程类别、状态、目标页数、事实版本、更新时间。
- `SourceDocument`：项目或知识库归属、文件名、类型、来源版本、摘要、解析状态、存储位置。
- `ParseBlock`：文件版本、段落/表格/PDF 页标识、文本及顺序。
- `Fact`：字段、原始值、确认值、单位、来源片段、确认状态、事实版本。
- `Requirement`：招标原文、类别、评分值（若有）、出处、响应章节、处理状态。
- `KnowledgeItem`：案例/规范类型、正文、来源、章节或条文位置、适用条件、版本及核验状态。
- `Template`：工程类别、章节层级、必选模块、Word 样式和篇幅配置。
- `Chapter` / `ChapterVersion`：所属项目、目录位置、正文、引用、依赖事实版本、生成方式及人工编辑记录。
- `Job`：任务类型、阶段、进度、状态、重试次数、错误信息和运行标识。
- `ReviewIssue`：检查类型、严重程度、位置、说明和处理状态。
- `Export`：文件位置、关联章节版本、审核状态、页数或未验证标记。

项目资料、知识库资料物理和逻辑隔离。跨项目知识检索只能返回被标为参考资料的知识条目，不得把其他项目事实写入当前项目事实。缺失值保持空值并形成缺口。导入规范只代表登记，初始核验状态为“待核验”。

DOCX 来源定位使用文件版本和段落/表格序号；PDF 使用文件版本和页码。每个章节版本保存输入事实版本，事实、目录或源文件发生相关变更时，将受影响章节和检查结果标记待复核，不自动覆盖人工修改内容。

## 5. API 契约

所有接口以 `/api` 为前缀，错误以稳定错误码和面向用户的中文说明返回。至少包括：

- `POST/GET /projects`、`GET /projects/{id}`
- `POST/GET /projects/{id}/documents`、`POST /documents/{id}/parse`、`GET /jobs/{id}`
- `GET/PUT /projects/{id}/facts`、`POST /projects/{id}/facts/confirm`
- `GET/PUT /projects/{id}/requirements`
- `GET/PUT /projects/{id}/outline`
- `GET/PUT /projects/{id}/chapters`、`POST /chapters/{id}/generate`
- `POST /projects/{id}/checks/run`、`GET /projects/{id}/issues`
- `POST /projects/{id}/exports`、`GET /exports/{id}/download`
- 知识条目导入、分类、检索和核验状态管理接口。

前端的上传、保存、重试、章节编辑、任务查询和下载必须调用后端真实实现。上传文件名不直接用作磁盘路径；限制文件类型和大小，生成内部文件名并按项目隔离存储。

## 6. 模型调用、错误与密钥

模型适配器只从后端读取 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL`。密钥不进入前端、日志、错误详情、源码或规格文件；本地 `.env` 由 `.gitignore` 排除。真实模型请求失败时记录可追踪的任务错误，不回退固定文本。缺少密钥时，解析、编辑和手工 DOCX 导出仍可用，模型生成操作明确显示未配置。

结构化模型输出经 Pydantic 校验；仅对可重试的格式/传输错误进行有限重试，保留最终错误。发送给模型的内容限于本章必要的招标片段、已确认事实及检索片段，并在界面说明使用的模型和资料范围。上传文件及检索文本均按不可信业务资料处理，其中的指令不得更改系统规则或触发无关操作。

任务采用持久化任务记录；启动时将遗留的运行中任务标成中断，提供显式重试。重试沿用任务关联并避免重复创建章节或导出记录。导出与章节内容采用版本关联。

## 7. 检查与 Word 导出

首版确定性检查包括项目名称/工期一致性、要求是否映射章节、必选章节缺失、残留占位符、引用是否存在、规范核验状态及事实版本过期。检查状态使用通过、发现问题、未检查、需人工判断；有映射不等于充分响应。语义质量检查、工程方案可行性及专业计算不宣称通过。

Word 文档包含可编辑标题、段落和表格，配置标题级别、编号、页眉页脚及目录域；设置打开时更新域。未使用 Word/WPS 渲染验证前，目录页码和实际页数显示未验证。默认导出为显著标识的审核稿；存在关键问题时不得标成已审核终稿。不得通过重复内容凑目标页数。

## 8. 测试与验收

自动化测试覆盖：

1. 未知项目值保持缺失，不能被模型输入或输出静默补齐。
2. 解析片段能回溯到 PDF 页或 DOCX 段落/表格位置。
3. 项目间事实不可串用；跨项目案例只能作为明确标识的参考。
4. 未核验规范不能被显示为已核验。
5. 项目事实变更会让依赖章节待复核，且保留人工编辑的旧版本。
6. 未配置密钥、模型 API 返回错误或结构化输出无效时显示真实失败状态，不触发模拟生成。
7. DOCX 能重新打开，包含预期章节及对应内容版本，并将未验证页数和待审状态写入导出记录。

端到端人工验收使用用户提供的真实招标文件：新建项目、上传解析、核对并修改事实、保存目录、调用 DeepSeek 生成一章、修改章节、运行检查、下载 DOCX、刷新页面确认数据仍在。具体文件需用户后续放入系统。短期验收验证流程贯通，不代表生成质量已经达到真实投标标准。
